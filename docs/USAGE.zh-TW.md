# 使用說明

## 1.2.2 resume255 更新

本資料夾附帶已核對雜湊的 PhotoRec／TestDisk 7.2。請保留 exe 旁的 vendor 與 licenses；無需另找 PhotoRec。鏡像計劃可勾選自動續批，仍受已批准累計上限和首次異常即停的限制；下方舊版單輪說明不適用於此選項。

### 接續中斷的 PhotoRec

1. 在「還原與預覽」按「接續中斷的 PhotoRec 提取（保存鏡像）」，選取原本的 PhotoRec 任務資料夾，不是單獨的 recovered.1 或來源盤。
2. 保留 recovery.json、input.img、photorec.ses 及所有 resume-... 資料夾。工具先重新核對暫存鏡像的完整雜湊，大鏡像可能需要等待。
3. 再次中斷時只採用最新一次已確認程序退出的斷點；缺失、損壞或退出不明時停止，不會退回舊進度。PhotoRec通常每5分鐘保存一次，太早中斷可能沒有斷點。
4. 新結果存於 resume-.../recovered.*；舊輸出保留，可能有重複候選。提取完成不代表影片或文件完整，不能據此刪除原鏡像。保留至少6GB空間，初次提取還需容納一份暫存鏡像。

### TestDisk 中文鏡像路徑

image-paths 版本支援來源鏡像含中文且沒有 Windows 短檔名的情況：工具會在目的端建立暫存副本，核對完整雜湊後才分析。目的端需有鏡像大小加6GB空間，並使用可被工具解析的英文／短檔名路徑，例如 R:\QuietRescue。停止或空間不足時不啟動 TestDisk，未完成的暫存檔標為 .partial。原鏡像保持只讀；正常分析結束只刪除程式自己的暫存副本。結果位址相對於所選鏡像，不能直接拿來寫實體分區表。

一個影片可能跨越多個1GB片段；單一片段即使雜湊正確，也可能缺少檔頭或後半部。可用「跨任務尋找並還原完整 MKV」檢查同一來源的保存任務；只有資料範圍完整覆蓋才匯出，不補零冒充完整影片。原檔名還原需要可解析MFT、可信分區幾何及全部資料範圍。

2026-10-24：此精確執行檔已通過管理員合成續讀、照片預覽與影片播放位置推進的程式化驗收；真實 PhotoRec 斷點續作另以原始碼流程驗證通過。這不是故障實體盤或人工視覺驗收。

## 基本操作（含舊版相容說明）

1. 解壓Windows ZIP，雙擊QuietRescue.exe並允許UAC，不需要安裝Python。PhotoRec的選配安裝見vendor/README.md；鏡像和內建照片還原不需要PhotoRec。
2. 點「刷新硬盤清單」，以型號、序號、容量和分區盤符確認來源。系統／開機碟不能選。同一物理盤下的分區會列在同一磁碟。目的資料夾必須在另一塊可識別的本機實體硬碟。
3. 起點／終點是物理 byte 位址，終點不含；須對齊512或4096邏輯扇區。起點預設0。GB欄是單輪上限，預設十進位1GB；單輪完成後需由使用者再次開始／續讀，目前沒有自動鏈接多輪。
4. 在「載入／同步進度 JSON」選取進度檢視器產生的 `progress.json`，色帶每5秒只讀更新；只有來源序號和容量完全相符才會套用。拖動游標會同步起點 bytes；藍色區塊標示本次 GB 範圍。綠色已保存、藍色已回報、紫色未確認、紅色故障、灰色未搶救、橙色避讓草案。此色帶不會讀取來源硬盤。
5. 「建立未審核計劃草案」只建立計劃，不會讀取來源。點「檢視並批准計劃」確認來源／目的序號、範圍、上限與避讓區間；批准紀錄綁定計劃 SHA-256。批准後按「開始／續讀」才開始。每請求1MiB、先持久化REQUESTED，再讀取並保存資料，之後記錄GOOD與SHA-256。首次讀錯、8秒回應超時或超過2秒慢讀即停；前後最多約1GiB是保守保護範圍，不是實測壞道邊界。作業系統／韌體內部重試不受程式控制。
5. 如果計劃配置了既有跳過／已嘗試地圖，程式會保存其基準並在讀取前檢查更新；出現新增保護範圍時封鎖讀取並要求重新建立計劃。映射損壞、不完整或匯入資料不可用時保持停讀。
6. 「安全停止」只提出停止請求；當前I/O返回並寫好資料及映射後才算結束。UI不可中斷校驗時會明示等待，不把按鈕點擊當作已停妥。保留整個任務資料夾：plan.json、approval.json、map.jsonl與chunk檔不可拆開。包括結果未確認的REQUESTED都會跳過，不可刪除紀錄強迫重讀。
7. 「驗證全部副本」只處理健康目的端已保存片段，不要求來源硬碟在線，也不會重新讀來源。已驗證容量不等於整盤完成，complete=false表示仍有缺口。「還原照片」從已驗證連續資料提取可解碼JPEG/PNG，候選緩衝上限64MiB，以雜湊命名，不能重建原檔名。
8. 「匯出完整.img」要求選定範圍無缺口，選定範圍不一定是整盤。「匯出已驗證連續區段」會附來源位址，不可跨缺口直接拼接。匯出需要額外空間且不可寫回來源實體盤。鏡像器保留5,000,000,000 bytes加32MiB；PhotoRec採定期空間檢查，並非檔案系統硬配額。
9. 將官方PhotoRec 7.2完整解壓到vendor/testdisk-7.2，再以「影片／更多格式 PhotoRec」處理匯出的副本。輸出必須在與鏡像不同的健康物理盤。以「載入還原的照片／影片資料夾」開啟結果；照片與支援編碼的影片可內嵌預覽，其他編碼用系統播放器開啟。需核對全片時長、跳轉與音訊，找到檔頭或程式正常退出不代表影片完整。
10. 「輸出只讀避讓分區預覽」從現有地圖整理讀錯、策略保護、結果未確認和未驗證區域，只產生JSON/CSV草案。候選段明確標示未證實健康；不寫分區表，不標稱精確壞道，也不含SMART壽命判定。本版本不提供CHKDSK /f、壞扇區寫入修復、格式化或分區表寫回。

## 常見問題

- UAC取消：不會啟動讀盤，準備好後再開啟；不要繞過系統安全機制。
- 序號缺失、跨盤卷或網路目的地：不支援，不要削弱身份檢查。
- 映射無效、雜湊不符、無法確認worker退出：保留映射、日誌與部分檔案，釐清結果前停止續讀。
- 掉線或新增讀取異常：保留斷點，重新開啟UI不會自動重試。
- 搶救目錄放在儲存庫外；不要把鏡像、序號、私人照片或完整日誌上傳GitHub。
- 舊任務缺少approval.json或計劃雜湊不符：實體續讀會封鎖。不要手工補造批准檔；請匯入／核對現有地圖並建立新的明確審核計劃。
